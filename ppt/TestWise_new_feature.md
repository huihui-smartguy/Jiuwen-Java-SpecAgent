# Testwise 测试看板总览界面 — 修改需求文档

> 目标地址：http://1.92.123.95/testwise/
> 文档版本：v1.1（新增「特性质量评估」卡片改造）｜ 日期：2026-07-23


## 一、修改点一：版本管理功能（新增）

### 1.1 功能说明

| 项 | 说明 |
|---|---|
| 版本枚举 | ① 合一版本630（key: `630`）　② 合一版本715（key: `715`） |
| 默认展示版本 | 默认 715（最新），切换展示 630（旧版）数据 |
| 切换效果 | 点击版本后，总览看板内全部数字（用例数、通过率、发现问题数、质量评分、各分维度及「特性质量评估」卡片各值）联动切换为对应版本数据，无需整页刷新 |
| 数据范围 | 每个版本对应一份完整且独立的看板数据集 |

### 1.2 交互与 UI 要求
- 切换器位置：看板【右上角 / 顶部 Tab】，沿用现有风格。
- 切换方式：点击切换，当前版本高亮；切换时展示 loading，避免数据闪烁/错位。
- 持久化（可选）：记录用户上次选中版本，刷新后保持。请确认是否需要。
- 空数据兜底：某版本暂无数据时给出明确提示，不报错。

### 1.3 数据结构建议
数据按版本维度组织，前端切换传入版本 key，后端按版本返回；或前端一次性拉取两版本数据本地切换：
```jsonc
{ "630": { /* 完整看板数据 */ }, "715": { /* 完整看板数据 */ } }
```
字段沿用现有结构，仅新增 `version` 维度区分。

## 二、修改点二：「基础功能」维度卡片结构改造（新增）

### 2.1 改造内容

在「基础功能」维度下：

| 操作 | 对象卡片 | 说明 |

## 四、验收标准

1. 版本切换器正确展示「合一版本630 / 合一版本715」，切换后所有数字正确联动，无残留/错位，具备 loading 与空数据兜底。
2. 「基础功能」维度下不再出现「整体质量评估」「发现问题」卡片；新增「特性质量评估」卡片，含 7 特性 × 6 指标，表头与字段口径与本文档一致。
3. 切换版本时，「特性质量评估」卡片数据随版本联动。
4. 「合一版本630」总览核心指标与「特性质量评估」各值与本文档填写值一致。
5. 「维度质量」卡片及其他维度（DFX/场景化/性能）保持不变。
