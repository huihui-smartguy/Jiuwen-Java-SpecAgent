# v3.1 AutoTestFlow Iteration 3 Full Pipeline Fixes / AutoTestFlow 第三轮全链路修复

## 中文

### 背景

本轮修复针对真实全链路运行中暴露的四类问题：远程源码 URL 被归一化为 `source.available=false` 后跳过 Stage 2，Stage 3 只留下零散 JSON 而缺少合并与 Markdown 伴生产物，Stage 5 后未按 `--remediate` 自动进入 Stage 6/7，以及 `analysis_output` 中报告、结果、QualityGates 等产物错误集中在 `FeatureAnalysis/`。

### 行为变更

- `sut_manifest.py` 支持解析 GitHub source URL，并在本地源码不可用时将仓库 clone 到 `<output_dir>/.state/source/`。成功后会设置 `source.available=true`、`source.abs_path=<clone_dir>`、`source.skip_code_scan=false`，并保留 `source.remote_url` 与 `source.resolution` 元数据；失败时保留不可用状态并记录 `source_remote_clone_failed`。
- Stage 2 编排说明改为使用 normalized manifest 中的 `source.abs_path` 执行 `prepare_code_scan.py`，确保远程源码成功解析后会进入代码扫描。
- Stage 3a/3b merge 成为强制门：`merge_enriched.py` 必须生成 `FeatureAnalysis/s3a_scenario_landscape.md`，`merge_test_design.py` 必须生成 `TestCases/test_design.json`、`TestCases/test_examples.md`、`TestCases/scene_tc_mapping.json`。
- `merge_test_design.py` 兼容并救援误写到 `FeatureAnalysis/test_cases/*.json` 或 `FeatureAnalysis/test_design_batch_*.json` 的用例文件，重新合并到 canonical `TestCases/`。
- `output_layout.py` 新增 `--migrate`，可将误放在 `FeatureAnalysis/` 或 `.state/` 的 Contract、KnowledgeBase、TestCases、TestRun、Reports、QualityGates 产物迁移到规范目录；已存在 canonical 文件时不覆盖，只报告 conflict。
- Stage 5 编排说明新增收尾步骤：先执行 artifact migration，再运行 `record_faults.py` 与 `professional_acceptance.py --mode report`，验证 `TestRun/case_results.json`、`Reports/report.md` 与 QualityGates 产物，然后根据 `--remediate` 决定是否进入 Stage 6/7。
- AutoTestFlow/TestKnowledgeBase 元数据与 Professional_experience 文档更新为 canonical `KnowledgeBase/`、`QualityGates/`、`TestRun/`、`Reports/` 路径，`.state` 仅作为 legacy fallback。

### 兼容性

- 旧 `.state/*` 与误放 `FeatureAnalysis/*` 产物仍可被脚本只读发现，并可通过 `output_layout.py --migrate` 迁移。
- GitHub clone 是 best-effort：私有仓、无 git、网络失败或分支不存在时不抛栈，仍保留 `remote_url` 与人工复核原因。
- 强断言仍只来自 `contract.md`；TestKnowledgeBase 与 Professional_experience 仍为知识/门禁/报告建议层。

### 验证

- 新增远程源码解析测试：clone 成功、clone 复用、clone 失败、遮蔽本地路径加公开 remote URL。
- 新增输出归档迁移测试：Reports、TestRun、QualityGates、KnowledgeBase、TestCases、Contract 迁移与 canonical conflict 保护。
- 新增 Stage 3 merge 回归：误写到 `FeatureAnalysis/test_cases/*.json` 的用例能合并为 canonical `TestCases/test_design.json` 与 `TestCases/test_examples.md`。

## English

### Background

This iteration fixes four issues observed in real full-pipeline runs: remote source URLs were normalized as `source.available=false` and skipped Stage 2, Stage 3 could leave only scattered JSON without merged Markdown companions, Stage 5 did not continue into Stage 6/7 despite remediation flags, and reports/results/QualityGates artifacts could be concentrated under `FeatureAnalysis/` instead of the canonical archive layout.

### Behavior Changes

- `sut_manifest.py` now resolves GitHub source URLs and clones them into `<output_dir>/.state/source/` when no usable local source path exists. On success it sets `source.available=true`, `source.abs_path=<clone_dir>`, `source.skip_code_scan=false`, and preserves `source.remote_url` plus `source.resolution` metadata. On failure it keeps the source unavailable and records `source_remote_clone_failed`.
- Stage 2 orchestration now uses `source.abs_path` from the normalized manifest when invoking `prepare_code_scan.py`, so a resolved remote source enters code scanning.
- Stage 3a/3b merges are mandatory gates: `merge_enriched.py` must render `FeatureAnalysis/s3a_scenario_landscape.md`, and `merge_test_design.py` must render `TestCases/test_design.json`, `TestCases/test_examples.md`, and `TestCases/scene_tc_mapping.json`.
- `merge_test_design.py` rescues case files misplaced under `FeatureAnalysis/test_cases/*.json` or `FeatureAnalysis/test_design_batch_*.json` and rewrites the canonical `TestCases/` outputs.
- `output_layout.py` adds `--migrate` to move misplaced Contract, KnowledgeBase, TestCases, TestRun, Reports, and QualityGates artifacts out of `FeatureAnalysis/` or `.state/`. Existing canonical files are never overwritten; conflicts are reported.
- Stage 5 orchestration now runs artifact migration, `record_faults.py`, and `professional_acceptance.py --mode report`, verifies `TestRun/case_results.json`, `Reports/report.md`, and QualityGates outputs, then uses `--remediate` to decide whether to continue into Stage 6/7.
- AutoTestFlow/TestKnowledgeBase metadata and Professional_experience docs now point to canonical `KnowledgeBase/`, `QualityGates/`, `TestRun/`, and `Reports/` paths, with `.state` retained only as legacy fallback.

### Compatibility

- Existing `.state/*` and misplaced `FeatureAnalysis/*` artifacts remain readable and can be migrated with `output_layout.py --migrate`.
- GitHub clone is best-effort: private repositories, missing git, network failure, or missing branches degrade gracefully with `remote_url` and review reasons preserved.
- Strong assertions still come only from `contract.md`; TestKnowledgeBase and Professional_experience remain advisory knowledge, gate, and reporting layers.

### Verification

- Added remote-source tests for clone success, clone reuse, clone failure, and redacted local path plus public remote URL.
- Added archive migration tests for Reports, TestRun, QualityGates, KnowledgeBase, TestCases, Contract, and canonical conflict protection.
- Added Stage 3 merge regression coverage for cases misplaced under `FeatureAnalysis/test_cases/*.json`.
