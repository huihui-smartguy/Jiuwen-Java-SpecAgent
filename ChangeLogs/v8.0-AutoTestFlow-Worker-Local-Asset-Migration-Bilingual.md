# v8.0 AutoTestFlow Worker-Local Asset Migration / AutoTestFlow Worker 本地资产迁移

## 中文

### 背景

上一轮重构已经把 AutoTestFlow 拆分为 Supervisor + 阶段 Worker 的工程组织形态，但根目录仍保留 `templates/`、`scripts/`、`shared/`、`reference/`、`examples/`、`beta/` 等执行资产。为了让每个阶段团队可以独立维护、直接引用本阶段资产，本轮进一步将执行资产迁移到 `AutoTestFlow/workers/` 下。

### 核心约束

- 公开调用仍然只有 `/auto-test-flow ...`。
- 不新增 StageTask、stage DAG、runtime helper、新 Worker 调用协议或新功能。
- 原阶段顺序、人工门、分类语义、最终结构化输出目录保持不变。
- `stage2 + stage2.5` 继续由 `Stage2-CodeAnalysisContract` 统一维护，并保持“先代码分析、再生成 `Contract/contract.md`”的内部顺序。

### 主要变更

- `AutoTestFlow/SKILL.md` 进一步精简为 Supervisor-only 入口，只保留公开命令、调度、门控和输出契约。
- 各 `AutoTestFlow/workers/Stage*/SKILL.md` 承接原阶段详细步骤、输入、输出、脚本/模板依赖和禁止事项。
- 阶段模板迁移到所属 Worker 的 `templates/`。
- 阶段脚本迁移到所属 Worker 的 `scripts/`。
- 仍跨阶段共享的确定性工具、schema、参考校验器迁移到 `AutoTestFlow/workers/_common/`。
- 黑盒测试参考脚手架迁移到 `Stage4-TestGenerationRun/reference/`。
- examples/demo 迁移到拥有对应流程的 Worker。
- beta wiki 预研资产迁移到 `Stage26-KnowledgeMatch/`。
- 删除根目录执行资产目录：`templates/`、`scripts/`、`shared/`、`reference/`、`examples/`、`beta/`。

### 验证

- 新增 Worker-local 路径完整性测试，确保根目录执行资产目录不存在，且 AutoTestFlow 内不再引用旧根目录执行路径。
- 保留原单元测试发现流程：`python3 -m unittest discover AutoTestFlow/tests`。
- 验证禁止新增的 runtime 概念文件不存在。
- 验证 manifest normalization、stage2 scan/contract、knowledge match、stage3b merge、stage4 aggregation、stage6/7 dry-run remediation 等既有脚本路径可从 Worker-local 位置执行。

## English

### Background

The previous refactor split AutoTestFlow into a Supervisor + stage Worker
engineering structure, but execution assets still lived in root-level
`templates/`, `scripts/`, `shared/`, `reference/`, `examples/`, and `beta/`
directories. This revision migrates those assets under `AutoTestFlow/workers/`
so each stage team can own and reference its assets directly.

### Constraints

- The only public invocation remains `/auto-test-flow ...`.
- No StageTask, stage DAG, runtime helper, new Worker invocation protocol, or
  new feature is introduced.
- The original stage order, human gates, classification semantics, and final
  structured output layout remain unchanged.
- `stage2 + stage2.5` remains owned by `Stage2-CodeAnalysisContract`, preserving
  the internal order: code analysis first, then `Contract/contract.md`.

### Changes

- `AutoTestFlow/SKILL.md` is slimmed further into a Supervisor-only entrypoint
  that preserves the public command, routing, gates, and output contract.
- Each `AutoTestFlow/workers/Stage*/SKILL.md` now owns the detailed original
  stage procedure, inputs, outputs, script/template dependencies, and
  prohibited changes.
- Stage templates move into the owning Worker's `templates/`.
- Stage scripts move into the owning Worker's `scripts/`.
- Still-shared deterministic utilities, schemas, and reference validators move
  into `AutoTestFlow/workers/_common/`.
- The black-box testing reference harness moves into
  `Stage4-TestGenerationRun/reference/`.
- Examples and demos move into the Worker that owns the workflow.
- Beta wiki research assets move into `Stage26-KnowledgeMatch/`.
- Root-level execution asset directories are removed: `templates/`, `scripts/`,
  `shared/`, `reference/`, `examples/`, and `beta/`.

### Validation

- Added Worker-local path integrity coverage to ensure root execution asset
  directories do not exist and AutoTestFlow no longer references old root
  execution paths.
- Preserved the original unit test discovery flow:
  `python3 -m unittest discover AutoTestFlow/tests`.
- Verified prohibited runtime concept files are absent.
- Verified existing script paths for manifest normalization, stage2
  scan/contract, knowledge match, stage3b merge, stage4 aggregation, and stage6/7
  dry-run remediation from Worker-local locations.
