# v7.0 AutoTestFlow Supervisor-Workers Stage Refactoring

# v7.0 AutoTestFlow 总控-阶段 Worker 重构

## 中文

### 背景

AutoTestFlow 的阶段越来越多，且部分阶段会面对大量 API、超大源码仓和长链路测试产物。为了降低单一编排上下文膨胀风险，并让不同工程师可以按阶段并行迭代，本次引入“Supervisor + 阶段 Worker”的工程组织方式。

### 关键约束

- 不新增功能；
- 不新增公开命令；
- `/auto-test-flow` 单一调用不变；
- 参数、阶段顺序、人工门、执行边界分类不变；
- 结构化输出路径不变；
- 不新增 StageTask、stage DAG、runtime helper 或新执行协议；
- `Contract/contract.md` 仍是可执行断言唯一强 Oracle；
- TestKnowledgeBase 仍是外部知识源，不把知识硬编码进 prompt。

### 关键设计

- `AutoTestFlow/SKILL.md` 继续作为唯一 public Supervisor。
- 新增 `AutoTestFlow/workers/` 作为阶段 Worker 组织目录。
- 每个 Worker `SKILL.md` 只记录原阶段职责、输入、输出、模板/脚本依赖和人工门。
- 原 stage2 与 stage2.5 合并为 `Stage2-CodeAnalysisContract`：代码分析完成后立即生成 `Contract/contract.md`。
- `AutoTestFlow/templates/` 与 `AutoTestFlow/scripts/` 继续作为短期 Worker 的实际执行资产。

### 短期重构

新增 Worker 目录：

- `Stage0-SutManifest`
- `Stage1-RequirementAnalysis`
- `Stage2-CodeAnalysisContract`
- `Stage26-KnowledgeMatch`
- `Stage3a-ScenarioEnrichment`
- `Stage3b-TestDesign`
- `Stage4-TestGenerationRun`
- `Stage5-Report`
- `Stage6-FaultAnalysis`
- `Stage7-ReverifyIssue`

更新 `AutoTestFlow/SKILL.md` 与 `AutoTestFlow/README.md`，只说明阶段 Worker 组织方式，不改变原执行流程。

### 长期迭代

- 为每个 Worker 增加 fixture 测试；
- 增加 owner/reviewer/changelog 等阶段维护元数据；
- 未来可选支持 A2A 远程 Worker，但远程产物必须先物化为本地版本化文件；
- 未来可选支持 MCP 工具源，但下游阶段只能消费本地 snapshot；
- 长任务可选增加 checkpoint/audit；
- Stage7 外发 issue 或未来不可逆动作必须保留人工门、配置门和审计记录。

### 验证方式

- 运行 `python3 -m unittest discover AutoTestFlow/tests`；
- 检查禁止新增的 StageTask/runtime/DAG 文件不存在；
- 检查 Worker 初版只引用原模板和脚本；
- 与 `origin/feature/refactoring-beta` 对比确认变更范围；
- 确认现有 demo 仍产出同名 canonical artifacts。

## English

### Background

AutoTestFlow now contains many stages, and some stages may face large API sets,
large source repositories, and long testing artifact chains. To reduce
single-orchestrator context pressure and allow engineers to iterate stages in
parallel, this change introduces a “Supervisor + stage Workers” engineering
organization.

### Key Constraints

- No new functionality.
- No new public command.
- The single `/auto-test-flow` invocation is unchanged.
- Parameters, stage order, human gates, and execution boundary classifications
  are unchanged.
- Structured output paths are unchanged.
- No StageTask, stage DAG, runtime helper, or new execution protocol is added.
- `Contract/contract.md` remains the only strong executable Oracle.
- TestKnowledgeBase remains an external knowledge source; knowledge is not
  hard-coded into prompts.

### Key Design

- `AutoTestFlow/SKILL.md` remains the only public Supervisor.
- `AutoTestFlow/workers/` is added as the stage Worker organization directory.
- Each Worker `SKILL.md` only records the original stage responsibility, inputs,
  outputs, template/script dependencies, and gates.
- Original stage2 and stage2.5 are merged into `Stage2-CodeAnalysisContract`:
  generate `Contract/contract.md` immediately after code analysis.
- `AutoTestFlow/templates/` and `AutoTestFlow/scripts/` remain the actual
  execution assets for short-term Workers.

### Short-Term Refactor

Added Worker directories:

- `Stage0-SutManifest`
- `Stage1-RequirementAnalysis`
- `Stage2-CodeAnalysisContract`
- `Stage26-KnowledgeMatch`
- `Stage3a-ScenarioEnrichment`
- `Stage3b-TestDesign`
- `Stage4-TestGenerationRun`
- `Stage5-Report`
- `Stage6-FaultAnalysis`
- `Stage7-ReverifyIssue`

Updated `AutoTestFlow/SKILL.md` and `AutoTestFlow/README.md` only to describe
the stage Worker organization, without changing the original execution flow.

### Long-Term Iteration

- Add fixture tests for each Worker.
- Add stage owner/reviewer/changelog metadata.
- Optionally support A2A remote Workers later, but remote outputs must first
  materialize as versioned local files.
- Optionally expose MCP tool sources later, but downstream stages consume only
  local snapshots.
- Optionally add checkpoint/audit support for long-running jobs.
- Stage7 issue submission or any future irreversible action must retain human
  gates, config gates, and audit records.

### Verification

- Run `python3 -m unittest discover AutoTestFlow/tests`.
- Confirm prohibited StageTask/runtime/DAG files do not exist.
- Confirm first-version Workers reference only original templates and scripts.
- Compare against `origin/feature/refactoring-beta` to confirm the change scope.
- Confirm existing demos still produce the same canonical artifacts.
